# Выбор языка и фреймворка для Backend (Core)

## Статус
Принято (Accepted)

## Контекст
Необходимо выбрать техстек для разработки бэкенда системы TourBooker, который будет обрабатывать бизнес-логику бронирования, управления турами и интеграции с платежными системами. PER-1

## Ограничения
1. **Высокая конкурентность (Concurrency):** При продаже «горящих» туров система должна обрабатывать большое количество одновременных запросов на бронирование без блокировок.
2. **Строгая типизация:** Финансовые операции и работа с датами (заезды/отъезды) требуют строгой типизации для избежания рантайм-ошибок.
3. **Производительность:** Время ответа API не должно превышать 100 мс при средней нагрузке.
4. **Экосистема:** Наличие готовых библиотек для работы с PostgreSQL, Redis и платежными шлюзами.

## Решение
Выбрать язык **C#** с использованием чистой архитектуры (Clean Architecture)

## Последствия
- **Плюсы:** Отличная поддержка многопоточности (корутины) для обработки пиковых нагрузок при бронировании; высокая скорость компиляции и выполнения; строгая типизация.
- **Минусы:** Меньше готовых "коробочных" решений по сравнению с Java/Spring.
- **Риски:** Необходимость наличия в команде разработчиков, знающих C#.
