# Выбор Frontend стека для веб-приложения

## Статус
Принято (Accepted)

## Контекст
Необходимо выбрать фреймворк для разработки пользовательского интерфейса (для туристов и туроператоров). Интерфейс должен быть интуитивным, адаптивным и быстрым.

## Ограничения
1. **SEO-оптимизация:** Страницы с турами должны идеально индексироваться поисковыми системами (Google, Яндекс) для привлечения органического трафика.
2. **Time to Interactive (TTI):** Первая отрисовка страницы не должна превышать 1.5 секунды на мобильных устройствах.
3. **Мультиязычность (i18n):** Встроенная поддержка переключения языков и локализации дат/валют.
4. **Адаптивность:** Полная поддержка мобильных устройств, планшетов и десктопов.

## Решение
Использовать **Next.js (на базе React)** с применением Server-Side Rendering (SSR) для публичных страниц (поиск, карточки туров) и Static Site Generation (SSG) для маркетинговых страниц. Панель туроператора реализовать как классическое SPA (Client-Side Rendering).

## Последствия
- **Плюсы:** Отличное SEO благодаря SSR; быстрый первый рендер; огромная экосистема React; встроенная поддержка i18n и оптимизации изображений в Next.js.
- **Минусы:** Требует более мощных серверов для рендеринга (по сравнению с чистым SPA); кривая обучения для разработчиков, не знакомых с концепциями SSR/SSG.
- **Риски:** Усложнение процесса деплоя (необходимость Node.js сервера, а не просто статического хостинга).
