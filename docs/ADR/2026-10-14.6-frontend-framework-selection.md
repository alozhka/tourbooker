# Выбор Frontend стека для веб-приложения

## Дата
14 октября 2026

## Статус
Принято (Accepted)

## Контекст
Необходимо выбрать фреймворк для разработки пользовательского интерфейса (для туристов, туроператоров и администраторов). Интерфейс должен быть интуитивным, адаптивным и быстрым.

## Ограничения
1. **SEO-оптимизация:** Страницы с турами должны идеально индексироваться поисковыми системами (Google, Яндекс) для привлечения органического трафика.
2. **Отрисовка основного контента:** Основной контент страницы должен отображаться не дольше 1,5 секунды на мобильных устройствах.
3. **Мультиязычность (i18n):** Встроенная поддержка переключения языков и локализации дат/валют.
4. **Адаптивность:** Полная поддержка мобильных устройств, планшетов и десктопов.

## Решение
Использовать **Next.js (на базе React)** с применением Server-Side Rendering (SSR) для публичных страниц (поиск, карточки туров) и Static Site Generation (SSG) для маркетинговых страниц. Кабинеты пользователей реализовать с Client-Side Rendering в одном общем приложении, разграничив доступ по ролям.
- Nginx служит единым публичным входом и завершает TLS. Запросы `/api/*`, включая платёжные вебхуки, направляются в WebService; остальные — в Next.js.
- Клиентский JavaScript в браузере обращается напрямую к `/api` через Nginx. Next.js не является промежуточным backend для этих запросов.
- Для SSR сервер Next.js получает публичные данные WebService по HTTP/JSON во внутренней сети. Next.js и его клиентский React-код выпускаются как одно веб-приложение.
- Роли и принадлежность объектов проверяются backend; скрытие элементов интерфейса не является механизмом авторизации.

## Последствия
- **Плюсы:** Отличное SEO благодаря SSR; быстрый первый рендер; огромная экосистема React; встроенная поддержка i18n и оптимизации изображений в Next.js.
- **Минусы:** Требует более мощных серверов для рендеринга (по сравнению с чистым SPA); кривая обучения для разработчиков, не знакомых с концепциями SSR/SSG.
- **Риски:** Усложнение процесса деплоя (необходимость Node.js сервера, а не просто статического хостинга).
